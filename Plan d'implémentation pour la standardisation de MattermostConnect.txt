## Objectifs et principes

Ce plan détaille l'implémentation complète de la standardisation de MattermostConnect, en suivant une approche méthodique qui tient compte des dépendances entre les différents groupes de travail.

### Principes directeurs
1. **Cohérence maximale**: Tous les composants suivront des patterns identiques
2. **Optimisation pour la production**: Code final prêt pour la mise en production
3. **Remplacement complet**: Aucune rétro-compatibilité n'est nécessaire
4. **Réutilisation systématique**: Les utilitaires, slices et helpers seront réutilisés partout
5. **DRY (Don't Repeat Yourself)**: Élimination de toute duplication de code

### Méthodologie de travail

Pour chaque groupe:
- Identification des fonctionnalités existantes à préserver
- Extraction et centralisation des patterns communs
- Implémentation cohérente dans tous les fichiers concernés
- Vérification systématique des duplications potentielles entre composants

## Groupe 1: Fondations communes et utilitaires de store

**Dépendances**: Aucune - Ce groupe constitue la fondation pour tous les autres

### Objectifs
Créer les fondations réutilisables pour tous les autres groupes: utilitaires Zustand, gestion d'état standardisée, système d'événements.

### Standardisation à appliquer
- Création de patterns Zustand réutilisables centralisés dans `storeUtils.ts`:
  ```typescript
  createStore<T>() // Création de store standard avec immer et devtools
  createPersistStore<T>() // Avec persistence locale
  createLoadingSlice<S>() // Slice standard pour états de chargement/erreur
  createAsyncAction<Args, Result>() // Helper pour actions asynchrones typées
  ```

- Implémentation d'un `CommonSlice` complet et réutilisable:
  ```typescript
  interface CommonState {
    // État
    isLoading: boolean;
    loadingIds: string[];
    error: Error | null;
    errors: Record<string, Error>;
    lastUpdated: number;
    lastFetchTimes: Record<string, number>;
    
    // Actions
    setLoading(isLoading: boolean): void;
    setLoadingId(id: string, isLoading: boolean): void;
    setError(error: Error | null): void;
    setErrorForId(id: string, error: Error | null): void;
    updateLastFetchTime(id: string): void;
    reset(): void;
  }
  ```

- Système d'événements optimisé et typé:
  ```typescript
  emitEvent<T>(type: EventType, data: T): void
  onEvent<T>(type: EventType, handler: (data: T) => void): () => void
  createTypedEmitter<T>(type: EventType): (data: T) => void
  createTypedListener<T>(type: EventType): (handler: (data: T) => void) => () => void
  ```

### Fichiers à modifier
- `src/core/store/storeUtils.ts`
- `src/core/store/slices/commonSlice.ts`
- `src/core/api/eventUtils.ts`
- `src/types/event.types.ts`

### Résultats attendus
- Fondations réutilisables pour tous les autres groupes
- Pattern commun pour la gestion d'état avec Zustand
- Système d'événements standardisé pour la communication inter-composants

## Groupe 6: Stores de base (auth et user)

**Dépendances**: Groupe 1, 2, 3 et 5 (utilise CommonSlice, gestion d'erreurs, services fondamentaux et services métier)

### Objectifs
Standardiser les stores d'authentification et utilisateur, qui sont les plus fondamentaux.

### Standardisation à appliquer
- Intégration complète avec `CommonSlice`:
  ```typescript
  export const useXXXStore = create<XXXStoreState>()(
    immer((set, get) => ({
      // Intégration du CommonSlice pour l'état partagé
      ...createCommonSlice<XXXStoreState>(set),
      
      // État spécifique
      specificState: initialSpecificState,
      
      // Actions spécifiques
      specificAction: (param: Type) => {
        set((state) => {
          // Modification immer
          state.specificState = newValue;
          // Utiliser les méthodes de CommonSlice
          updateLastFetchTime('key');
        });
      },
    }))
  );
  ```

- Délégation systématique aux services:
  ```typescript
  // Avant: Logique directement dans le store
  doSomething: (data) => {
    set((state) => {
      // Logique complexe ici
    });
  },
  
  // Après: Délégation au service
  doSomething: (data) => {
    const result = xxxService.process(data);
    set((state) => {
      state.something = result;
    });
  },
  ```

- Émission standardisée d'événements:
  ```typescript
  action: (param: Type) => {
    // Logique de l'action
    
    // Émission d'événement typée et cohérente
    emitEvent(EventType.XXX_HAPPENED, { param, result });
  },
  ```

### Fichiers à modifier
- `src/core/store/authStore.ts`
- `src/core/store/userStore.ts`
- `src/core/store/userSettingsStore.ts`

### Résultats attendus
- Stores standardisés utilisant les patterns communs
- Délégation de la logique métier aux services
- Émission cohérente d'événements

  ```typescript

  getFormattedName: (id) => {

  ```
