## Vue d'ensemble

Le module `src/internal` contient les composants internes et les utilitaires qui soutiennent l'architecture de MattermostConnect. Ces modules ne sont pas destinés à être utilisés directement par les consommateurs de la bibliothèque, mais plutôt à fournir une base solide et cohérente pour les composants de niveau supérieur.

L'architecture interne suit plusieurs principes clés :

1. **Séparation des responsabilités** : Chaque module a une responsabilité unique et bien définie
2. **Réutilisabilité maximale** : Les composants sont conçus pour être réutilisés dans différents contextes
3. **Typage fort** : Utilisation extensive de TypeScript pour garantir la sécurité des types
4. **Performance optimisée** : Utilisation de techniques avancées pour minimiser les rendus inutiles
5. **Cohérence architecturale** : Patterns cohérents à travers tous les modules

L'organisation générale est la suivante :

```
src/internal/
├── theme/                  # Configuration du thème Material-UI
├── types/                  # Définitions de types et interfaces
├── utils/                  # Utilitaires partagés
├── hooks/                  # Hooks React personnalisés
├── providers/              # Providers React pour le contexte
└── hoc/                    # Higher-Order Components
```

### Architecture et principes

Le système de thème suit plusieurs principes :

1. **Cohérence visuelle** : Application uniforme des couleurs, espacements et typographie
2. **Personnalisation flexible** : Possibilité de surcharger le thème par défaut
3. **Sémantique des couleurs** : Utilisation cohérente des couleurs pour les états et actions
4. **Accessibilité** : Respect des contrastes pour l'accessibilité

### Configuration du thème (`themeConfig.tsx`)

Ce fichier définit la configuration par défaut pour le thème Material-UI, avec :

- Palette de couleurs (primaire, secondaire, erreur, avertissement, etc.)
- Typographie (famille de police, tailles, pondérations)
- Surcharges de composants (boutons, cartes, champs, etc.)

```typescript
// Exemple simplifié de configuration de thème
export const defaultThemeOptions: ThemeOptions = {
  palette: {
    primary: {
      main: "#1976d2",
      // Autres nuances...
    },
    // Autres couleurs...
  },
  typography: {
    fontFamily: '"Roboto", "Helvetica", "Arial", sans-serif',
    // Autres configurations...
  },
  components: {
    MuiButton: {
      styleOverrides: {
        // Surcharges...
      }
    },
    // Autres composants...
  }
};
```

La fonction `createCustomTheme` permet de créer un thème personnalisé en fusionnant les options par défaut avec des options personnalisées :

```typescript
export const createCustomTheme = (options?: ThemeOptions): Theme => {
  return createTheme({
    ...defaultThemeOptions,
    ...options,
  });
};
```

Le thème par défaut est exporté pour une utilisation immédiate :

```typescript
export const defaultTheme = createCustomTheme();
```

```typescript
// Types principaux simplifiés
interface DialogConfig {
  id: string;
  type: "confirm" | "alert" | "form" | "custom";
  title: string;
  message?: string;
  confirmText?: string;
  cancelText?: string;
  isDestructive?: boolean;
  isLoading?: boolean;
  onConfirm?: () => void | Promise<void>;
  onCancel?: () => void;
  preventBackdropClose?: boolean;
  component?: React.ReactNode;
  maxWidth?: "xs" | "sm" | "md" | "lg" | "xl" | false;
}

interface DialogContextValue {
  openDialog: (dialog: Omit<DialogConfig, "id">) => string;
  closeDialog: (id: string) => void;
  closeAllDialogs: () => void;
  confirm: (options: ConfirmDialogOptions) => string;
  alert: (options: AlertDialogOptions) => string;
  custom: (options: CustomDialogOptions) => string;
}
```

Fonctionnalités principales :
- Système centralisé pour gérer tous les dialogues de l'application
- Support pour différents types de dialogues (confirmation, alerte, formulaire, personnalisé)
- Gestion des états de chargement pour les actions asynchrones
- Prévention des clics multiples
- File d'attente pour éviter l'empilement des dialogues
- API simplifiée pour les types de dialogues courants
- Support pour les composants personnalisés dans les dialogues

Le provider gère le rendu de tous les dialogues actifs et expose un hook `useDialog` pour accéder au contexte :

```typescript
export function useDialog(): DialogContextValue {
  const context = useContext(DialogContext);
  if (context === undefined) {
    throw new Error("useDialog must be used within a DialogProvider");
  }
  return context;
}
```

## Conclusion

L'architecture interne de MattermostConnect offre une base solide et cohérente pour le développement des composants de niveau supérieur. La séparation claire des responsabilités, la réutilisabilité maximale, et l'attention portée aux performances font de cette architecture un exemple d'organisation moderne pour une bibliothèque de composants React.

Les principes clés qui ressortent de cette analyse sont :

1. **Modularité** : Chaque module a une responsabilité unique et bien définie
2. **Cohérence** : Patterns et APIs cohérents à travers tous les modules
