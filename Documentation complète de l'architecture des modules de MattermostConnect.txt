## Module hooks

Le module `hooks` fournit des abstractions réutilisables pour accéder aux fonctionnalités du système via des hooks React personnalisés. Ces hooks servent de pont entre les composants UI et la couche métier.

### Organisation du module

```
src/hooks/
├── index.ts                     # Point d'entrée et exportation centralisée
├── useAuth.tsx                  # Hooks d'authentification
├── useChannels.tsx              # Hooks de gestion des canaux
├── useDirectChannels.tsx        # Hooks pour canaux directs
├── useDirectChannelUsers.tsx    # Hooks pour utilisateurs de canaux directs
├── useEntityQuery.tsx           # Hook générique pour requêtes d'entités
├── useMessages.tsx              # Hooks de gestion des messages
├── useTeams.tsx                 # Hooks de gestion des équipes
├── useUnreadCounts.tsx          # Hooks pour compteurs de non-lus
├── useUsers.tsx                 # Hooks de gestion des utilisateurs
└── useWebSocket.tsx             # Hooks de gestion WebSocket
```

### Architecture et principes

Les hooks suivent une structure cohérente et des principes communs :

1. **Abstraction des stores et services** : Chaque hook encapsule la logique d'accès aux stores Zustand et aux services métier
2. **Optimisation des performances** : Utilisation extensive de `useMemo` et `useCallback` pour éviter les re-rendus
3. **Gestion des erreurs** : Utilisation du système centralisé de gestion d'erreurs
4. **Standardisation** : Interface cohérente pour tous les hooks du même type
5. **Composition** : Les hooks complexes sont souvent composés de hooks plus simples

### Hook générique pour requêtes d'entités (`useEntityQuery.tsx`)

Fournit un hook générique pour les opérations CRUD sur n'importe quel type d'entité.

```typescript
// Hook exporté
useEntityQuery<T extends Entity>(options: EntityQueryOptions<T>): {
  // Data
  data: T[];
  byId: Record<string, T>;
  ids: string[];
  
  // State
  isLoading: boolean;
  isFetching: boolean;
  error: ApiError | null;
  
  // Actions
  refetch(): Promise<T[]>;
  fetchById(id: string): Promise<T | null>;
  getById(id: string): T | undefined;
  create(data: Partial<T>): Promise<T>;
  update(id: string, data: Partial<T>): Promise<T>;
  remove(id: string): Promise<void>;
  
  // Raw mutations
  createMutation: UseMutationResult<T, ApiError, Partial<T>>;
  updateMutation: UseMutationResult<T, ApiError, { id: string; data: Partial<T> }>;
  deleteMutation: UseMutationResult<void, ApiError, string>;
}
```

## Module types

Le module `types` définit toutes les interfaces, types et enums utilisés dans l'application. Il fournit un système de typage cohérent et complet.

### Organisation du module

```
src/types/
├── index.ts                 # Point d'entrée et exportation centralisée
├── auth.types.ts            # Types liés à l'authentification
├── channel.types.ts         # Types liés aux canaux
├── common.ts                # Types communs et partagés
├── error.types.ts           # Types liés aux erreurs
├── event.types.ts           # Types liés aux événements
├── message.types.ts         # Types liés aux messages
├── reaction.types.ts        # Types liés aux réactions
├── settings.types.ts        # Types liés aux paramètres utilisateur
├── team.types.ts            # Types liés aux équipes
├── unread.types.ts          # Types liés aux compteurs non-lus
├── user.types.ts            # Types liés aux utilisateurs
└── websocket.types.ts       # Types liés au WebSocket
```

### Architecture et principes

Le système de types suit plusieurs principes :

1. **Séparation par domaine** : Types organisés par domaine métier
2. **Standardisation** : Patterns cohérents pour tous les types (états, stores, actions)
3. **Héritage** : Utilisation d'interfaces de base communes (Entity, WithTimestamps, etc.)
4. **Discrimination** : Types discriminés pour faciliter le filtrage et le type narrowing
5. **Documentation** : Commentaires JSDoc pour documenter les interfaces et leurs champs

## Module providers

Le module `providers` fournit des composants React qui initialient et configurent l'application.

### Organisation du module

```
src/providers/
├── index.ts                    # Point d'entrée et exportation centralisée
└── MattermostProvider.tsx      # Provider principal pour l'initialisation
```

### Architecture et principes

Le module providers suit plusieurs principes :

1. **Initialisation complète** : Gère l'initialisation de l'API, de l'authentification et du WebSocket
2. **Configuration flexible** : Supporte plusieurs modes (direct, proxy) et options
3. **Composition** : Utilise des sous-composants spécialisés pour chaque aspect de l'initialisation
4. **Isolation** : Isole l'initialisation de la logique applicative
5. **Performance** : Optimise pour éviter les rendus inutiles

### Provider Mattermost (`MattermostProvider.tsx`)

Le provider principal qui initialise tous les aspects de l'application.

```typescript
// Types
export interface MattermostProviderProps {
  children: ReactNode;
  serverUrl?: string;           // URL du serveur pour le mode direct
  proxyUrl?: string;            // URL du proxy pour le mode proxy
  clientId?: string;            // ID client pour le mode proxy
  token?: string;               // Token d'authentification
  enableWebSocket?: boolean;    // Activer la connexion WebSocket
  persistAuth?: boolean;        // Persister l'authentification
  onInitialized?: (success: boolean) => void;     // Callback d'initialisation
  onAuthError?: (error: Error) => void;           // Callback d'erreur d'auth
  onWebSocketError?: (error: Error) => void;      // Callback d'erreur WebSocket
}

// Sous-composants d'initialisation
const ApiConfigInitializer: React.FC<{
  serverUrl?: string;
  proxyUrl?: string;
  clientId?: string;
  token?: string;
  onError?: (error: Error) => void;
}>;

const AuthInitializer: React.FC<{
  token?: string;
  persistAuth?: boolean;
  onInitialized?: (success: boolean) => void;
  onError?: (error: Error) => void;
}>;

const WebSocketInitializer: React.FC<{
  mode: "direct" | "proxy";
  serverUrl?: string;
  proxyUrl?: string;
  clientId?: string;
  enabled?: boolean;
  onError?: (error: Error) => void;
}>;

const DataInitializer: React.FC<{
  enabled?: boolean;
}>;

// Provider principal
export const MattermostProvider: React.FC<MattermostProviderProps>;

// Variante pour le mode direct
export const MattermostDirectProvider: React.FC<
  Omit<MattermostProviderProps, "proxyUrl" | "clientId"> & {
    serverUrl: string;
  }
>;

// Variante pour le mode proxy
export const MattermostProxyProvider: React.FC<
  Omit<MattermostProviderProps, "serverUrl"> & {
    proxyUrl: string;
    clientId: string;
  }
>;
```

Le provider orchestre l'initialisation en plusieurs étapes :

1. **Configuration API** : Configure le client API avec les paramètres fournis
2. **Initialisation Auth** : Initialise l'authentification et restaure la session si possible
3. **Connexion WebSocket** : Établit une connexion WebSocket si activée
4. **Chargement des données initiales** : Charge les données initiales comme les compteurs non-lus
